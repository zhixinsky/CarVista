# 旅幕 0.3.5

默认开启“原尺寸直接替换（不处理画面）”。按导入图片的原始像素生成 CPBitmap，应用时直接写入该文件字节。不按旧缓存尺寸缩放、裁剪、补边，不要求新旧图片同尺寸。保留目标身份检查、自动备份、过期文件拒写和回读校验。车机可能自行缩放或裁剪，显示效果需要实测；不能承诺无缝拼接。请重新导入原图，旧版已经裁掉的内容无法恢复。固定像素和文件大小限制已解除，实际处理能力受系统与内存限制。

应用已更名为“旅幕”。为保持覆盖升级和已有数据兼容，工程名、Bundle ID 与 App Group 保持原值。第三方模块的作者署名与许可证保持完整。

面向自有 iPhone 的 CarPlay 自定义壁纸实验版本。当前已实现完整操作流程，但 iOS 27.2 / iPhone 16 Pro Max / 真实车机效果尚未验证；不能将编译通过等同于设备兼容性通过。

## 功能

- 首页统一为“壁纸 / 历史记录 / CarPlay 壁纸缓存 / 设置”，首次使用四步指南。
- App 图标、启动画面与一致的品牌样式；图标源文件与生成提示见 Design/。
- 未连接车机也能选图裁剪、制作本地 CPBitmap，支持深色、浅色与两者一起生成。
- 深浅色文件在历史中合并展示；支持详情预览、分享、重命名、删除单条与清空本地记录。
- 照片和裁剪草稿自动保留，清除设置不会删除历史或恢复备份。
- 基于 WQFiles / worse_query 的 App Group 访问后端，快速定位和可停止的完整容器扫描。
- 仅识别 `com.apple.CarPlayWallpaper`，在其 Library/Caches 下发现实际 CPBitmap，不写死颜色或 `-14` 后缀。
- 读取目标尺寸、深浅色分类；解码失败或尺寸异常时禁止替换。
- 相册选图、拖动定位与缩放预览；生成并回读验证 CPBitmap。
- 应用时自动适配目标缓存尺寸，不同宽高比采用居中裁剪。配对的深浅色可一次应用；多文件操作逐个执行，部分失败会明确报告成功数量，不宣称全部成功。
- 写入前备份，原位写入并回读校验；拒绝扫描后已变化的目标；备份历史恢复。
- 诊断报告导出。若访问或格式不兼容，会明确失败，不假装成功。

## 安装与测试

GitHub Actions 产物为 `LvMu-resign.ipa`。它带有 ad-hoc 签名和 App Group entitlement，**不能直接安装**，必须通过签名工具授予有效 App Group 并重新签名。AltStore / SideStore 等支持 App Group 的流程可作为选择；仅保留 entitlement 文本不代表具备权限。普通企业通配符 profile 通常不满足条件。

1. 签名安装后，在说明页确认 App Group 不为空。
2. 停车后连接 CarPlay，切换几张内置图片壁纸生成缓存。
3. 打开“壁纸”选图裁剪，点击“生成本地 CPBitmap”，选择深色、浅色或两者并保存。
4. 在保存后的详情或历史记录中选择“应用到 CarPlay 壁纸”，应用会查找缓存。未找到时可“继续查找”；选中目标后确认应用。
5. 重启 iPhone 并连接车机观察。应用无法自行确认车机显示结果。
6. 如需还原，扫描确认容器后在恢复页选备份，恢复后重启验证。

系统容器访问受版本、签名和权限影响。若缓存格式已不再是 CPBitmap，此版本会报告未找到可识别文件，不会修改未知格式。不要卸载应用来“恢复壁纸”：卸载会删除本应用内备份，而系统缓存修改可能仍然保留。

## 构建

macOS + Xcode + XcodeGen：在 ios 目录执行 `xcodegen generate`，打开 `CarCanvasWorkshop.xcodeproj`。本地真机签名需为自己的 Bundle ID 创建并授予 App Group。

`.github/workflows/ios-diagnostics.yml` 在 main 更新后自动编译。流水线先运行裁剪/扫描测试和上游文件写入与容器解析回归测试，再编译真机 arm64 应用，打包并生成 SHA-256。

## 测试边界

主机测试覆盖裁剪覆盖范围、比例保持、文件变化比较、符号链接排除、缺失目录错误、旧版历史兼容，以及上游备份/写入/恢复/解析回归。模拟器 UI 测试打开四个首页入口和首次指南并导出截图。这些测试不会修改手机系统容器。

尚须真机验证：实际签名权限、令牌获取、容器识别、私有 CPBitmap API 的当前行为、断电情形和车机加载结果。原位写入保留 inode，但不能保证面对突然断电或系统并发写入时完全原子化。
